# 视觉系统

用于缺少现有设计系统、需要补齐角色或评估视觉一致性时。以下数值是极简风起点，不是固定标准；已有有效规范时映射到原有角色，不另建平行体系。

阅读顺序：视觉基线 → 语义化变量 → 颜色应用 → 排版 → 布局与响应式 → 动效 → 主题适配。组件规格见 [组件设计](components.md)，状态行为见 [交互与可用性](interaction-and-accessibility.md)。

## 视觉基线

让界面像一份组织清楚的工作材料：能快速找到标题、对象、状态和下一步动作。视觉上的克制来自信息有序，留白、细边界和柔和文字只是实现方式。

| 页面类型 | 视觉重点 | 默认策略 |
| --- | --- | --- |
| 表单与工作流 | 下一步动作、填写顺序、错误位置 | 紧凑内容列，字段分组，主操作清楚 |
| 控制台与数据页 | 扫描效率、筛选范围、行列对齐 | 同类数值对齐，密度一致，保留必要分隔 |
| 阅读与内容页 | 连续阅读、标题层级、正文长度 | 限制行宽，增加段间距，弱化外围操作 |
| 对话与创作工具 | 内容流、输入焦点、任务状态 | 主内容占据主体，工具操作集中在输入区周围 |
| 产品介绍与营销 | 信息叙述、品牌识别、转化路径 | 标题与节奏更鲜明，装饰服务叙述 |

选择一个主要布局密度并贯穿同一类页面。卡片、表格和弹窗可以有不同密度，但同角色组件在不同位置应保持可辨认的一致性。

## 语义化变量

基础值描述“是什么”，语义角色描述“用在哪里”。例如基础灰阶可供 `text-secondary` 和 `border-control` 引用，但两者不能因为初始颜色相同就合并成一个业务角色。

组件优先使用语义角色。CSS 变量、主题对象或工具类均可，不强制特定命名或 DTCG 文件格式。调色板是参考值，最终以实现中的单一来源为准。

下面是独立新项目可选的浅色示例。引入前检查前缀冲突；已有体系时仅借用角色划分。

```css
:root {
  /* 基础值 */
  --mui-neutral-0: #ffffff;
  --mui-neutral-50: #f7f7f7;
  --mui-neutral-200: #e5e5e5;
  --mui-neutral-500: #858585;
  --mui-neutral-600: #666666;
  --mui-neutral-900: #191919;
  --mui-neutral-950: #0e0e0e;
  --mui-red-50: #fef3f2;
  --mui-red-700: #b42318;
  --mui-red-800: #912018;

  /* 语义角色 */
  --mui-surface: var(--mui-neutral-0);
  --mui-surface-muted: var(--mui-neutral-50);
  --mui-text: var(--mui-neutral-900);
  --mui-text-secondary: var(--mui-neutral-600);
  --mui-text-placeholder: var(--mui-neutral-600);
  --mui-text-on-action: var(--mui-neutral-0);
  --mui-action: var(--mui-neutral-900);
  --mui-action-hover: var(--mui-neutral-950);
  --mui-border-decorative: var(--mui-neutral-200);
  --mui-border-control: var(--mui-neutral-500);
  --mui-focus: var(--mui-neutral-900);
  --mui-error-text: var(--mui-red-700);
  --mui-error-surface: var(--mui-red-50);
  --mui-danger-action: var(--mui-red-700);
  --mui-danger-action-hover: var(--mui-red-800);
  --mui-text-on-danger: var(--mui-neutral-0);
  --mui-radius-control: 8px;
  --mui-radius-panel: 12px;
  --mui-radius-dialog: 20px;
  --mui-radius-pill: 9999px;
  --mui-duration-feedback: 140ms;
}
```

`border-decorative` 用于装饰分组；若输入框轮廓是识别其为控件的必要线索，使用 `border-control` 等满足对比要求的角色。不要把所有浅边框都归为“装饰”。

示例中 `#191919` 对白色约 17.58:1，`#666666` 对白色约 5.74:1；`#b42318` 对 `#fef3f2` 约 6.05:1。它们只说明指定前景与背景的组合，不保证叠加透明度或改背景后的结果。

状态色按含义配置，可增加 success、warning、info、图表和 diff 角色。品牌色、文字色和按钮填色不必共用一个变量；不同用途可能需要不同深浅。暗色主题需重新映射角色并检查各状态，不能直接反相。

## 颜色应用

### 把颜色分配给角色

| 角色 | 默认处理 | 使用说明 |
| --- | --- | --- |
| 页面与内容表面 | 白色与浅灰 | 用少量表面层次区分主区、侧栏、分组，不给每块内容都铺底 |
| 正文与标题 | 深灰至柔黑 | 主要层级优先通过字号、字重和位置建立 |
| 辅助文字 | 稳定可读的中灰 | 帮助说明和元数据仍需可读，不用“越次要越透明”无限变浅 |
| 主要操作 | 柔黑底与浅字 | 只突出当前任务的重要动作，次要动作降低视觉重量 |
| 选中与激活 | 轻填充、标记或边线 | 同时保留文字或形状差异，选择状态不能只在鼠标悬停时出现 |
| 危险与错误 | 与普通操作有区别的颜色及文字 | 危险动作、验证错误和系统异常可共享语义家族，不必共享同一色值 |
| 装饰分隔 | 较浅灰线 | 只负责组织信息；不能拿来代替必要控件边界 |

### 反馈色示例

下面是浅色主题可选组合。它们表达含义，不规定所有项目必须采用同一颜色。

| 状态 | 文字色 | 弱背景 | 配套文字或形状 |
| --- | --- | --- | --- |
| 成功 | `#166534` | `#f0fdf4` | “已完成”、对勾或完成数量 |
| 警告 | `#92400e` | `#fffbeb` | “需要处理”、警示图标及下一步 |
| 提示 | `#1d4ed8` | `#eff6ff` | 提示内容与可选操作 |
| 错误 | `#b42318` | `#fef3f2` | 错误原因及修复入口 |

引入时为这些组合建立语义角色；组件不要散落复制色值。图表分类色需要在相邻系列之间保持可区分，并通过图例、标签或线型辅助理解。Diff 内容除了红绿，也应有新增/删除标记。

### 表面、透明度与阴影

- 内容卡片默认平面或轻描边，悬浮菜单与弹窗可以用阴影建立覆盖关系。
- 遮罩用于降低背景干扰，透明度根据前景和背景实测；不要把某个透明度硬套所有主题。
- 半透明玻璃表面仅在引导或品牌表现确有需要时使用。检查最不利背景，确保标题、正文与控件都清楚。
- 给支持不足或用户降低视觉效果的环境提供实色表面；内容与操作不能依赖模糊效果才成立。
- Hover 改变颜色时，重新检查文字和图标对比。整体 opacity 会同时影响文字与背景，需要一起评估。

## 排版

| 角色 | 默认字号 | 行高起点 | 建议用途 |
| --- | --- | --- | --- |
| 营销大标题 | 36–60px，随可用宽度缩放 | 1.15–1.3 | 落地页主叙述 |
| 页面标题 | 28–32px | 1.25–1.4 | 页面与主要区块 |
| 组件标题 | 18–24px | 1.3–1.5 | 卡片与弹窗 |
| 正文 | 16px，密集工具页可用 14px | 1.5–1.7 | 可连续阅读内容 |
| 标签与辅助信息 | 14px | 1.4–1.6 | 字段标签、说明、元数据 |
| 次要短注 | 12px 起，按实际渲染调整 | 1.5 | 非核心短注，不用于挤压关键内容 |

- 系统字体栈可从 `system-ui, -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif` 起步；实际字体取决于平台、字符和可用字体。
- 400/500/600 是克制风格的常用起点，不能据此断言中文只允许某档字重。检查字体提供的字重及实际回退；品牌需要时可以使用更粗字重。
- 正文不默认压缩字距。中文长标题先检查换行和行高；英文大标题可适量收紧字距，不把负字距套到所有语言。
- 用 rem 或项目既有可缩放方案实现文字，检查缩放后的完整性。不要因字号表而拒绝有明确用途的中间档位。
- 数值比较时可用等宽数字；日期、货币和数字按产品语言、地区、币种和时区格式化，不把人民币格式作为全局默认。

### 字体层级怎样落到页面

一个设置页可以使用 30px 页面标题、20px 分组标题、14–16px 字段文字和 14px 帮助说明。不要仅为了强调某个字段，再叠加超粗字重、彩色文字和更大的字号。

列表元数据通常保持同一字号，通过位置和弱化颜色与正文区分。金额、计数和持续时间优先保证数字对齐；错误说明优先保证能读懂，不应因其处于辅助位置就缩小到难以阅读。

| 内容情况 | 处理方式 |
| --- | --- |
| 中文长标题 | 允许自然换行，检查行高和孤立短行，先调整容器宽度 |
| 英文长单词、文件名与链接 | 按内容选择换行、截断或完整查看入口 |
| 中英混排 | 统一产品的空格与标点约定，避免人工空格破坏机器可复制内容 |
| 数字变化 | 为计数保留合理宽度，必要时使用 `font-variant-numeric: tabular-nums` |
| 截断正文 | 只截断不影响判断的内容，并提供获取完整内容的方式 |

`title` 属性可以补充信息，但不应成为触屏或键盘用户获取关键内容的唯一入口。

## 布局、圆角与层次

- 间距可从 4、8、12、16、24、32、48、64px 选择。相同关系保持一致，比机械限制“只能是 8 的倍数”更重要。
- 卡片内边距从 16–24px 起步；主操作区域保持呼吸感，表格和工具栏根据密度缩减。
- 阅读区从约 40–48rem 最大宽度起步；控制台根据表格、侧栏和任务复杂度扩展。断点由内容开始拥挤的位置决定。
- 先保证窄屏单列可操作，再按空间增强列数。长表格必要时局部横滚；不让整个页面因固定宽度溢出。
- 8px 控件、12px 面板、20px 弹窗和全圆 chip 是一套可用起点。嵌套圆角可参考 `内半径 ≈ max(0, 外半径 − 内缩距离)`，仅用于真正平行内缩的轮廓，不强套所有子元素。
- 分隔线是否缩进由信息分组决定；对齐内容列即可，不规定必须用独立 div 或禁止容器 border。
- 默认平面卡片；菜单、对话框等浮层可用克制阴影辅助层级。营销背景、插图与品牌效果在任务需要时使用，不延伸成所有页面的装饰。

### 间距按关系组织

| 关系 | 默认间距起点 | 调整依据 |
| --- | --- | --- |
| 图标与文字、标签与字段 | 4–8px | 是否能被看作同一组 |
| 相邻操作、同组字段 | 8–16px | 点击目标、信息长度与密度 |
| 卡片内内容组 | 16–24px | 扫描顺序与容器大小 |
| 应用内主要区块 | 24–48px | 信息分组和页面滚动长度 |
| 营销叙述章节 | 48–96px | 阅读节奏、图像比例与屏幕高度 |

同一张卡片内，标题到描述通常比卡片到下一张卡片更近。通过这种距离关系，让用户不依赖每段边框也能理解分组。

### 响应式布局

先观察内容在哪个宽度开始挤压，再决定重排点。断点改变布局关系：侧栏收起、操作栏换行、列表变单列，而不是只把所有元素等比例缩小。

以下是内容容器和自适应网格的局部 CSS 示例。`18rem` 表示卡片所需宽度起点，应按实际内容调整。

```css
.page-shell {
  width: min(100% - 2rem, 75rem);
  margin-inline: auto;
  padding-block: 2rem;
}

.reading-column {
  max-width: 46rem;
}

.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 18rem), 1fr));
  gap: 1.5rem;
}

.toolbar {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 0.75rem;
}
```

检查窄屏时同时放入长标题、多位金额、完整错误提示和多按钮操作。必要时把低频操作收进清楚的菜单，保留当前任务的主操作。表格确需横向空间时，让表格区域滚动，并保证行操作仍可到达。

### 固定区域和浮层

侧栏、页头、底部操作栏与弹窗需要明确覆盖顺序。沿用项目的层级变量，避免组件随手加入越来越大的 z-index。

粘性操作栏需为正文预留空间；滚动到错误字段或键盘焦点时，目标不能被遮住。弹窗内部滚动与页面滚动的边界要清楚，关闭后应恢复合理的阅读位置。

## 动效与反馈

| 用途 | 默认处理 | 什么时候调整 |
| --- | --- | --- |
| 按钮、标签的状态反馈 | 约 120–180ms 的颜色过渡 | 既有组件体系已有节奏时沿用 |
| 菜单、弹窗进入退出 | 约 160–240ms 的轻量变化 | 需要保持空间连续性时使用小幅位移 |
| 页面内容入场 | 可省略，或用于明确叙述节奏 | 营销内容可更丰富，工作流页面优先即时可用 |
| 加载反馈 | 与真实 pending 状态同步 | 进度能力决定显示方式，详见交互章节 |

这些时长只是风格起点。动画不应使用户等待已经可用的内容，也不应让同一操作区持续移动。

```css
.action {
  transition:
    background-color var(--mui-duration-feedback) ease,
    color var(--mui-duration-feedback) ease,
    border-color var(--mui-duration-feedback) ease;
}

@media (prefers-reduced-motion: reduce) {
  .action {
    transition: none;
  }
}
```

入场效果在脚本未运行时仍需显示正文。停止位移或闪烁后，选中、步骤定位和完成状态继续以静态方式表达。JavaScript 驱动的效果也需要对应处理，不能只依赖 CSS 媒体查询。

## 品牌与主题适配

### 已有品牌

先识别品牌色目前承担的是按钮、链接、插图还是装饰角色。同一品牌原色未必适合小号文字，可以为文本与填充分别选择同色系的可读版本。

沿用现有字体、图标和组件形态，集中统一本次任务涉及的间距、状态与语义。只有在用户明确要求建立新系统时，才调整全局设计语言。

### 暗色主题

| 语义角色 | 浅色示例 | 暗色示例 |
| --- | --- | --- |
| 主表面 | `#ffffff` | `#161616` |
| 次表面 | `#f7f7f7` | `#222222` |
| 主要文字 | `#191919` | `#f5f5f5` |
| 辅助文字 | `#666666` | `#b3b3b3` |
| 装饰分隔 | `#e5e5e5` | `#3c3c3c` |
| 控件边界 | `#858585` | `#888888` |
| 焦点指示 | `#191919` | `#f5f5f5` |

这张表用于说明角色映射，并非一套完整暗色主题。主要操作的前景/背景、危险操作、选中填充、图表和图片均需一起适配；透明表面与浮层尤其要检查实际叠加结果。

### 调整检查

- 角色一致：同类文字、操作和边界仍有稳定用途。
- 对比有效：普通、hover、selected、focus 等相关状态分别查看。
- 层级清楚：主次内容仍能通过结构、位置和字重判断。
- 语义完整：错误、成功与选中不只靠颜色表达。
- 范围可控：局部需求没有顺带改变未涉及的页面或依赖。

## 组件的一致性

| 元素 | 默认处理 | 需要避免的误导 |
| --- | --- | --- |
| 主要操作 | 深底浅字，动作文案清楚 | 所有按钮同样抢眼，或把危险操作伪装成普通继续 |
| 次要操作 | 描边或轻填充 | 仅在 hover 后才可辨认是控件 |
| 只读标签 | 安静的文字或弱底 | 没有交互却出现手型、点击反馈 |
| 筛选 chip | 显示选中状态，支持对应键盘交互 | 只靠圆角暗示可点击或只靠颜色表示选中 |
| 图标 | 沿用一个主要图标体系，尺寸和视觉重量一致 | 用没有名称的图标承担关键动作 |
| 文中链接 | 与正文可辨，默认保留下划线等非颜色线索 | 黑白极简导致链接与普通文字无法区分 |

圆角不能代替语义、标签和交互反馈。带文字按钮可以有帮助识别的图标，不强制删除下载、外链等有效提示；装饰图标不重复进入可访问名称。默认不用 emoji 装饰业务界面，但用户内容与既有品牌约定不在全局清除范围内。
