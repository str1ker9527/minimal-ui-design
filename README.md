# 极简前端设计 Skill

**Minimal UI Design Skill** — 一个可安装的前端设计 Skill，用于设计、实现和审查网页 UI。调用名称为 `$minimal-ui-design`。

帮助设计和开发保持统一的视觉语言，并把组件状态、交互反馈与可用性落实到页面中。

默认风格是克制的极简：清楚的文字层级、中性色、适度留白、轻量边界和必要动效。它也能配合已有品牌、暗色主题、数据密集布局与组件库工作。

## 快速调用

安装并被 Codex 识别后，输入技能名和你的需求即可：

```text
$minimal-ui-design 帮我设计这个页面
```

也可以在输入框键入 `$`，从技能列表选择 **“极简前端设计 Skill”**，再补充需求。

| 想做什么 | 调用示例 |
| --- | --- |
| 新建页面 | `$minimal-ui-design 做一个资料上传页面` |
| 改善现有页面 | `$minimal-ui-design 优化当前页面，保留已有品牌` |
| 只做审查 | `$minimal-ui-design 检查当前页面，先列问题` |

已安装并加载时，相关 UI 设计任务也可由 Codex 根据技能描述自动选用；需要明确指定时，直接写 `$minimal-ui-design`。无须使用固定的“使用某技能”句式。

## 适用场景

- 从零建立一个轻量网页产品的视觉基线。
- 整理控制台、内容工具、表单或 AI 对话界面的组件一致性。
- 在既有产品中新增页面，让新功能接上已有设计语言。
- 审查页面里的视觉层级、状态反馈、错误恢复和键盘操作问题。

营销页可以采用这套规则组织信息与交互，再按品牌需要加入更鲜明的视觉表达。密集数据页则可以缩小留白、提高信息密度，同时保持文字可读、操作可辨。

## 设计主张

### 先让任务清楚

用户应能判断自己在哪里、当前可以做什么、操作后发生了什么。页面首先建立清楚的标题、信息分组和主要动作，再用颜色、图标和动效补充表达。

### 用一致的角色组织视觉

正文、辅助说明、主要操作、危险操作、装饰边界和控件边界各有角色。用设计变量管理这些角色，可以让颜色、主题和密度变化有明确的调整位置。

### 极简也要表达状态

选中、聚焦、加载、失败、成功和不可用应当能被识别。保留必要的标签、对比度、状态色和恢复入口，让视觉上的克制服务于使用过程。

### 让默认值接受项目约束

默认值解决没有既定规范时的起步问题。接入现有产品时，优先沿用它的品牌、组件和技术栈；根据任务补齐缺口，保持局部改动的边界。

## 如何使用

简短调用适合任务已经明确的情况。需要控制交付范围时，再说明页面目标、现有项目材料和希望得到的结果，例如下面的完整示例。

### 新建页面

> $minimal-ui-design 为资料管理工具实现上传页面。没有既有设计系统，采用默认极简风。包含文件选择、上传中、失败重试和上传完成状态。接口不提供进度百分比。

### 延续现有品牌

> $minimal-ui-design 改进当前数据控制台，保留深色主题、品牌主色、组件库和表格密度。重点处理筛选区、行内操作和空状态。

### 只做审查

> $minimal-ui-design 审查这组页面，按影响排序列出问题、位置与建议。先给审查结果，不修改代码。

### 调整组件

> $minimal-ui-design 整理设置页里的按钮、输入框和确认弹窗，让同类操作保持一致，并检查键盘焦点与错误提示。

## 你会得到什么

| 任务形式 | 交付内容 |
| --- | --- |
| 设计方案 | 页面结构、关键组件、设计变量与必要状态说明 |
| 实现页面 | 对应代码或可运行页面、实际完成的检查与仍待验证的部分 |
| 界面审查 | 按影响排序的问题、具体位置、用户影响和建议处理方式 |
| 规范整理 | 与现有项目衔接的视觉角色、组件规则和使用例子 |

代码与样式示例用于表达设计意图和局部实现方式。接入项目时，需要结合现有路由、数据、组件行为和构建方式完成验证。
